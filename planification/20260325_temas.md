# Sistema de temas — 2026-03-25

## Objetivo

Permitir a Anna elegir desde el backoffice entre distintos diseños predefinidos de la web pública. Cada tema tiene sus propios templates Twig y CSS, completamente independientes entre sí.

---

## Decisiones de diseño

- **Mecanismo**: Custom Twig Loader (`ThemeAwareTwigLoader`) que intercepta la resolución de templates públicos. Los controllers no cambian.
- **Fallback**: si un tema no define un template concreto, se usa el template existente (los actuales son el tema por defecto).
- **Temas disponibles**: definidos en un enum PHP `Theme`. Añadir un tema = añadir un case + crear su carpeta con templates.
- **Persistencia**: tabla `settings` (clave/valor) en BD. Clave `active_theme`.
- **No customizable**: Anna elige entre opciones predefinidas, no puede editar nada.

## Estructura de carpetas por tema

```
src/Infrastructure/Http/View/public/           ← templates actuales = fallback (default)
src/Infrastructure/Http/View/public/themes/
    minimal/
        layout.html.twig
        home/index.html.twig
        gallery/by_category.html.twig
        ...
    bold/
        layout.html.twig
        ...
```

## Steps

### Step 1 — Migración: tabla `settings`

Crear migración Doctrine que añade la tabla `settings`:
- `key` VARCHAR(100) PRIMARY KEY
- `value` TEXT NOT NULL

Insertar fila por defecto: `('active_theme', 'default')`.

---

### Step 2 — Domain: Setting + Theme enum

**`Domain/Setting/Entity/Setting.php`**
- Atributos: `key` (string), `value` (string)
- Factory: `Setting::create(string $key, string $value): self`
- Getters: `key()`, `value()`
- Método: `setValue(string $value): void`

**`Domain/Setting/Repository/SettingRepository.php`**
- `findByKey(string $key): ?Setting`
- `save(Setting $setting): void`

**`Domain/Theme/Theme.php`** — enum
```php
enum Theme: string
{
    case Default = 'default';
    // Futuros temas se añaden aquí
}

public static function labels(): array  // nombre legible por tema
public function label(): string
```

---

### Step 3 — Infrastructure: DoctrineSettingRepository

`Infrastructure/Persistence/Doctrine/DoctrineSettingRepository.php`
- Implementa `SettingRepository`
- `findByKey`: busca por PK
- `save`: persist + flush

---

### Step 4 — Application: servicios de tema

**`Application/Setting/GetActiveTheme/GetActiveThemeService.php`**
- Lee `active_theme` de la BD
- Si no existe, devuelve `Theme::Default`

**`Application/Setting/UpdateActiveTheme/UpdateActiveThemeCommand.php`**
- `theme: Theme`

**`Application/Setting/UpdateActiveTheme/UpdateActiveThemeService.php`**
- Recibe el command
- Busca o crea el setting `active_theme`
- Guarda el nuevo valor

---

### Step 5 — ThemeAwareTwigLoader

`Infrastructure/Twig/ThemeAwareTwigLoader.php`

Implementa `Twig\Loader\LoaderInterface`. Lógica:

1. Recibe el nombre de template (ej: `public/home/index.html.twig`)
2. Si empieza por `public/` y NO por `public/themes/`:
   - Obtiene el tema activo (cacheado en la request)
   - Si tema !== 'default': comprueba si existe `public/themes/{tema}/{resto}`
   - Si existe → lo sirve
   - Si no → delega al loader por defecto
3. Si no empieza por `public/` → delega directamente al loader por defecto

Registrar en `services.yaml` con tag `twig.loader` y prioridad alta (100).

---

### Step 6 — Twig Extension: global `activeTheme`

`Infrastructure/Twig/ActiveThemeExtension.php`

Implementa `AbstractExtension`. Método `getGlobals()` devuelve `['activeTheme' => $theme]`.
Útil para usar `{{ activeTheme }}` en templates (por ejemplo en el layout admin para mostrar el tema activo).

Registrar como servicio con tag `twig.extension`.

---

### Step 7 — AdminThemeController

`Infrastructure/Http/Controller/Admin/AdminThemeController.php`

- `GET /admin/tema` → muestra selector con todos los temas del enum (`Theme::cases()`)
- `POST /admin/tema` → llama a `UpdateActiveThemeService` y redirige con flash de confirmación

---

### Step 8 — Vista admin: selector de temas

`Infrastructure/Http/View/admin/theme/index.html.twig`

- Grid de tarjetas, una por tema
- Cada tarjeta muestra: nombre del tema, descripción breve (del enum), indicador de "activo"
- Botón "Activar" en los que no están activos

---

### Step 9 — Enlace en el menú del admin

Añadir enlace "Diseño" en `admin/layout.html.twig` apuntando a `/admin/tema`.

---

### Step 10 — Registrar servicios y rutas

- `services.yaml`: registrar `ThemeAwareTwigLoader`, `ActiveThemeExtension`, `AdminThemeController`, repositories y services nuevos
- Rutas: añadir las dos rutas del `AdminThemeController` (ya se definen con atributos)

---

### Step 11 — Tests

- `ThemeAwareTwigLoaderTest` (unit): verifica que redirige al template del tema si existe, y hace fallback si no
- `UpdateActiveThemeServiceTest` (integration): verifica que guarda y recupera correctamente el tema activo

---

### Step 12 — Smoke test manual

1. Ir a `/admin/tema` → ver el selector con "default" activo
2. Activar otro tema (cuando exista) → verificar que la web pública cambia
3. Volver a "default" → verificar que restaura

---

## Notas

- Por ahora solo existe el tema `default` (los templates actuales). La infraestructura queda lista para añadir temas nuevos.
- Añadir un tema nuevo en el futuro: (1) añadir case al enum, (2) crear carpeta `themes/{nombre}/` con sus templates. Sin cambios en código.
